# Project decisions

| ID | Decision | Basis / limitation |
|---|---|---|
| D001 | Surabaya November1945, Jembatan Merah–Kali Mas district | User-approved setting. Date-specific combat moment not yet selected. |
| D002 | Blender5.2 + existing BlenderMCP via OpenCode/DeepSeek | User environment. Exact app/addon/model-provider versions detected at runtime. |
| D003 | Realistic architecture mainly seen from above, selected closer views | User accepted recommended direction. |
| D004 | Editable Blender deliverable; no web viewer | User preference. |
| D005 | Roughly1.5km-square working extent | M001 crop[2460,3700,3720,4960], graphical-scale approximation1.19m/px. |
| D006 | Local image-derived coordinate frame, no EPSG | No global georeferencing or residual calculation performed. |
| D007 | Architecture-first base with separate time-specific props/damage | Available appearance images mostly prewar; exact target condition unproved. |
| D008 | Source-map index1 retains P.W.D. identity | M001 building index. No automatic Internatio identification. |
| D009 | Landmark footprint/height adjustments remain explicit | Photos/modern visiting pins are not1945survey data. |
| D010 | Files and copied scene checkpoints are recovery authority | Automatic context compaction is lossy. |
| D011 | Street rows are typological reconstructions, not a surveyed inventory | M001 gives alignments only. Module widths, storey mix, facade colours, shopfront detail and roof forms are authored variation seeded deterministically; frontages stop at a 3.8 m sidewalk and landmark/bridge/water keepouts. Rear ranges and the 414 background terraces (1443 units) are authored urban depth, explicitly `hypothetical` in asset metadata. Kembang Djepoen uses the L008-derived vocabulary; other roads transfer the same family. Signboards stay blank. |
| D013 | Materials are generated from a single parameter file, not hand-built per material | `output/material_palette.json` holds every base colour, tint, roughness, UV repeat and EEVEE setting; `apply_06_materials.py` rebuilds 30 owned node trees from it. B&W photographs establish tonal relationships, not exact paint hues, so all colours are recorded as `reconstructed`. Facades tint the shared plaster set by desaturate-then-multiply so texture detail survives; the earlier luminance-ramp approach flattened walls to flat colour. Texture sets A001-A004 are production resources, not historical evidence. |
| D014 | Glazing uses an explicit Fresnel sheen mix rather than pure physical glass | EEVEE screen-space tracing cannot sample the sky on a vertical shopfront panel, so a purely physical dark glass rendered as a black void. A Layer Weight Fresnel ramp mixes a sky-toned sheen, modulated by object-space noise so a row does not read as one flat band. This is a deliberate rendering compromise and is visually plausible, not physically exact. |
| D015 | Background parcels are authored urban depth on a quantised parcel grid | Parcel pitch 25 m (frontage) x 34 m (depth), widths 23.2-24.8 m, depths 14-16 m, orientation quantised to 15 degrees, with a courtyard rear range. 883 parcels / 1563 units. Tagged `hypothetical`. This replaces isolated scatter, which read as a toy model, but it is still not a building inventory and must not be read as one. |
| D016 | Daylight is a neutral review rig, not a dated or weather-specific condition | Sky gradient strength 1.25, sun 3.2 energy at 41 degrees elevation, 2.2 degree disc, exposure 0.15, AgX Medium High Contrast, EEVEE fast GI at 6 m. Azimuth and elevation were chosen to model the architecture and are not from a dated ephemeris. No rain, smoke, fire, ash or rubble is added anywhere in the scene. |
| D012 | streets-01 recovered by deterministic headless rebuild, GUI session left untouched | The live Blender GUI's MCP addon socket accepted connections but stopped executing code (no response to `get_scene_info`/`execute_code`), so the unsaved live streets scene could not be saved or inspected. `output/build_scripts/build_05_streets.py` is the construction record; it was rerun in `blender --background` from the singa-01 checkpoint into the new path `output/working/streets-01.blend`. Nothing was written to `singa-01.blend` or to the GUI session. The addon needs Stop/Start in Blender's BlenderMCP sidebar panel before interactive MCP work resumes. |

| D017 | MCP bridge re-verified working; the D012 "dead socket" was a one-off hang | A `{"type":"execute","code":...,"strict_json":false}` request, JSON terminated with a NUL byte, sent to 127.0.0.1:9876 on 2026-10-24 returned `{"status":"ok"}` and reported the live GUI scene (`singa-01.blend`, 137 objects, dirty). The add-on is Blender Lab `MCP` 1.0.3, enabled, and defines **no** 3D Viewport sidebar panel: its `Start MCP Bridge Server` / `Stop MCP Server` operators are drawn in the add-on preferences, i.e. Edit > Preferences > Add-ons > MCP. Earlier advice to find a Stop/Start button in an N-panel beside Blendkit was wrong and is corrected in `NEXT_STEPS.md` and `output/DELIVERY_REPORT.md`. No headless-rebuild work needs to be undone: those rebuilds are the authoritative construction record either way. |
